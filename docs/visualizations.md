# Visualization boundary

`packages/visualization` is a portable contract for visual answers. Accepted model payloads are bounded bar charts, line charts, tables, and a small structured document tree. Document nodes use a fixed text/tag vocabulary; no arbitrary attributes, JavaScript, HTML, CSS, SVG, URLs, or callbacks are accepted. A source response without a valid document remains ordinary text.

The backend must call `parseDraft` on untrusted output, verify the source assistant message belongs to the active thread/account, then call `sealDocument` with **server-derived** identity, message revision, ID, and timestamp. Do not accept the origin fields from the model or client. Persist the sealed document and its revocation status in the single storage-owner process.

Every list, fetch, stream replay, and export needs a fresh authorization check. Load the current authenticated account, thread owner, source message and revision, and revocation status from storage. Pass those values to `canReadDocument`; deny on false. On source deletion, replacement, thread transfer, logout, or explicit document revocation, the next read must fail. Do not treat a previously issued URL or client cache as authority. Responses should use `Cache-Control: no-store`.

The server must send a bounded envelope with account, thread, access epoch, and a lease of at most five seconds. `parseEnvelope` rejects cross-scope documents. `VisualizationLease` holds only an ephemeral display copy and clears it on account/thread/epoch mismatch, expiry, or failed refresh. The desktop has the same lease and closed-shape checks in `apps/desktop/src/visualization.rs`, plus a `render_native` helper using GPUI primitives. The chat view requests authorized envelopes and clears its display on logout, context change, reconnect failure, and authority errors. All strings enter GPUI as text, not markup. Numeric axes come from trusted code using finite values.

## Integration status

The self-hosted backend seals a document from an admitted assistant turn and stores it in the owning account's catalog. `GET /v1/sessions/:id/visualizations` reloads the Pi assistant source and verifies its current revision before returning a five-second lease. The account gateway authenticates every read, and GPUI parses the lease against its current account and session before rendering it inside the conversation. `/viz` exercises this path with a deterministic offline chart; mocked provider output can use the same versioned data prefix. There is no public visualization creation route. Account changes and source deletion or replacement must remain serialized with publication if those mutations are added later. No browser cookies or existing ChatGPT credentials are imported.
